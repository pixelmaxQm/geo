/collect/run 分阶段修复方案

先保证采集结果完整和失败可诊断，再做二维码登录态。请看整体流程是否符合你的预期。

阶段 1：采集结果与失败日志
API 模式
平台原始响应 → rawResponse 全量保存
搜索/引用列表 → 按返回顺序标准化保存到 citations
前端结果表 → 可展开查看全部引用源
Playwright 模式
页面加载 / 登录阻断 / 输入失败 / 超时 → 全部写入 run log
失败时截图 → screenshotPath 保存
result.status=failed，errorMsg + rawResponse 可诊断
阶段 2：二维码登录态
平台配置页 / 登录弹窗
选择 Playwright 平台 → 点击“登录授权”
后端打开登录页 → 截取二维码图片
前端展示二维码 + 登录状态轮询
扫码成功 → 保存 storageState/cookie/session
后续采集 → 自动加载该平台登录态
A

按这个两阶段做

阶段 1 先解决当前 /collect/run 结果和失败日志；阶段 2 做二维码登录。

B

登录能力提前

第一阶段就把登录任务和 session 保存一起做，避免 Playwright 测试反复失败。

C

先只做 API

先把 API 搜索/引用内容完整存储跑通，Playwright 另起任务。
